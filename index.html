03 · Password

🔒 Password seeds pixel visit order (SHA-256 → numpy permutation) and AES-256-GCM key (PBKDF2 × 100 000 rounds). Both are required to decode.

Algorithm Pipeline

1
Build Payload
Detect file type → choose strategy: text/JSON → zlib level-9; audio/video/zip → raw; images → try compress. Then AES-256-GCM encrypt (PBKDF2 key, fresh salt).
2
Compute Cost Map
scipy.ndimage: cost = 1/(σ²_local + min(∇h,∇v) + ε). Used only for NC-LSBM direction — not for pixel ordering.
3
Order Pixels
SHA-256(password)[:8] → numpy seed → full H×W×3 permutation. Pixel-value independent — encode and decode always agree.
4
NC-LSBM Embed (vectorized)
np.unpackbits → all bits at once. Per modified pixel: choose ±1 closer to (left+right)/2. No Python loop — full numpy speed.
5
Return Stego PNG
Lossless PNG returned from server. Visually identical to cover. No algorithm in browser.

Cost Function

Adaptive Modification Cost
cost(r,c,ch) = 1 / ( σ²_local + min(∇h, ∇v) + ε )
σ²_local — 5×5 box variance via scipy.ndimage.uniform_filter
∇h — |pixel[r, c+1] − pixel[r, c−1]| (horizontal)
∇v — |pixel[r+1, c] − pixel[r−1, c]| (vertical)
min(∇h, ∇v) — WOW insight: safe only if complex in ALL directions
ε = 0.001 — division-by-zero guard

Pixel Ordering

Pure Password-Keyed Permutation
seed = SHA-256(password)[:8] → uint64
perm = numpy.random.default_rng(seed).permutation(H×W×3)

The permutation depends only on the password and image dimensions — not on pixel values. This ensures encode and decode visit exactly the same pixels in the same order, even after NC-LSBM has modified pixel values by ±1.

NC-LSBM — Novel Contribution

Neighborhood-Consistent LSB Matching
Standard LSBM
LSB ≠ target?
→ random ±1 (coin flip)
→ 50% suboptimal choices
→ larger SRM residual
NC-LSBM (this work)
LSB ≠ target?
→ compute neighbor avg
→ pick ±1 closer to avg
→ always optimal
result = argmind ∈ {+1,−1} | (v + d) − avg(neighbors) |
Proof: min(a,b) ≤ (a+b)/2 always →
NC-LSBM residual ≤ LSBM expected residual
for every single modified pixel. Provable, not empirical.

Binary Header Layout
Bytes 0– 3 4 B magic "STEG"
Bytes 4–19 16 B PBKDF2-SHA256 salt
Bytes 20–31 12 B AES-GCM nonce
Bytes 32–35 4 B uint32 BE original file size
Bytes 36–39 4 B uint32 BE ciphertext length
Byte 40 1 B uint8 filename length N
Bytes 41… N B UTF-8 filename
… 1 B uint8 MIME length M
… M B UTF-8 MIME type
Remaining AES-256-GCM ciphertext
(compressed plaintext + 16 B auth tag)

Security Properties

Without the password:
· Pixel visit order is unknown (SHA-256 permutation)
· Extracted bits are indistinguishable from noise
· Even knowing MAGIC_BYTES, AES-GCM auth tag fails

PBKDF2 parameters:
· Algorithm: SHA-256
· Iterations: 100 000 rounds
· Output: 32 bytes (AES-256 key)
· Fresh 16-byte salt per encode — rainbow tables useless
